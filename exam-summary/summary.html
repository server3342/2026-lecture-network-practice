H · 2주차 · HTTP와 에이전트 실습 §2.1–2.2

H1 HTTP 핵심

  • HTTP는 클라이언트–서버 프로토콜이다. TCP 80을 쓴다(HTTPS는 443).
  • HTTP는 무상태(stateless)다. 서버는 클라이언트 상태를 보관하지 않는다. 쿠키가 상태를 더한다.
  • 비지속 연결: 객체마다 TCP 연결을 하나 연다. 객체 하나에 2·RTT + 전송 시간이 든다.
  • 지속 연결(HTTP/1.1 기본): 연결 하나로 여러 객체를 보낸다. 첫 객체는 2·RTT, 다음 객체는 약 1·RTT다.
  • HTTP/1.1은 객체를 차례대로 보낸다. 큰 객체가 작은 객체를 막는다(HOL 블로킹).
  • HTTP/2는 객체를 프레임으로 나누고 한 TCP 연결에 섞어 보낸다. 그래도 TCP 손실은 모든 스트림을 막는다.
  • HTTP/3는 UDP 위의 QUIC을 쓴다. 스트림마다 신뢰성을 따로 처리한다. 한 스트림의 손실이 다른 스트림을 막지 않는다. 전송·TLS 핸드셰이크를 합친다(1 RTT, 재접속 0-RTT).
  • 웹 캐시(프록시)는 응답 시간과 접속 링크 부하를 줄인다. 조건부 GET은 If-Modified-Since를 보낸다. 바뀌지 않았으면 304 Not Modified가 온다.

H3 에이전트 실습 요점

  • Task 1: 에이전트가 자료(HTTP/QUIC의 RFC, 논문)를 모은다.
  • Task 2: 주장을 하나씩 직접 확인한다. 틀린 주장의 수를 센다.
  • Task 3: 작업 설정(AGENTS.md)을 개선한다. 다시 센다.
  • 요점: "완성되어 보인다"와 "맞다"는 다르다. 모든 주장을 원문과 대조한다.

D · 3주차 · DNS, CDN §2.4.2–2.4.3, §2.5

D1 계층과 이름 풀이

  • DNS는 분산된 계층형 데이터베이스다. 각 단계는 아래 존(zone)을 위임한다.
  • 단계: 루트 → TLD(.com, .kr) → 권한 서버(korea.ac.kr).
  • 루트는 호스트 주소를 모른다. 루트는 TLD 서버만 안다. 그래서 위임(referral)을 돌려준다.
  • 호스트는 로컬 리졸버에 재귀 질의 1번을 보낸다(RD=1).
  • 리졸버는 루트, TLD, 권한 서버에 반복 질의를 보낸다(RD=0, +norecurse).
  • 측정: www.korea.ac.kr은 서버 3곳(루트 → .kr → 학교)에 물었다.
  • Glue = NS 이름의 A 레코드다. Additional 섹션에 온다. NS 이름이 위임된 존 안에 있으면 부모가 glue를 준다.
  • Glue 없음: NS 이름이 다른 도메인에 있다. 리졸버는 NS 이름을 루트부터 먼저 풀어야 한다. 즉 두 번째 탐색이다. 측정: www.nytimes.com에서 질의 +3건(총 13건).
  • 실습 요구 R1–R6: (주소, 경로)를 돌려준다. 루트에서 시작한다. 재귀 질의를 쓰지 않는다. glue 없음 처리(R3). 응답 없으면 다음 서버(R4). CNAME이면 처음부터 다시(R5). 깊이 제한(R6).

D4 캐시와 TTL (Task 3)

  • TTL은 권한 서버가 정한 "이 시간까지만 믿어도 된다"는 값이다.
  • 올바른 캐시는 레코드를 그 레코드의 TTL 동안만 보관한다. 만료 시각 = now + ttl을 저장한다.
  • baseline 문제 1(정확성): 수명을 60초로 고정한다. 짧은 TTL 레코드를 만료 뒤에도 준다 → stale 266건.
  • baseline 문제 2(성능): 긴 TTL 레코드도 60초 뒤 버린다 → 불필요한 상류 질의. 리스트 선형 탐색도 느리다.
  • 원인은 같다. baseline이 TTL을 버린다.
  • 하한: 만료 뒤 첫 질의는 반드시 상류로 간다. 어떤 올바른 캐시도 이것을 피할 수 없다. 하한 = 275 = 내 결과.
  • 최악의 레코드: www.microsoft.com. TTL 20초이고 질의가 가장 많다(322건 중 189건 stale).

D5 CDN, 유도(steering), DASH (Task 2)

  • 사이트는 CNAME 체인으로 CDN을 가리킨다(예: → akamaiedge.net).
  • 어떤 CDN은 애니캐스트를 쓴다. IP 하나, 위치 여러 곳, CNAME 없음.
  • Netflix는 netflix.com 안에서 끝난다. 자체 CDN을 운영한다.
  • "마지막 두 레이블 비교" 규칙은 www.wikipedia.org → wikimedia.org에서 틀린다. 존은 다르지만 소유자는 같다. CNAME은 이름을 보여 줄 뿐 소유자를 보여 주지 않는다.
  • 측정: 12곳 중 10곳이 CNAME으로 CDN에 연결. 10곳 중 8곳은 리졸버를 바꾸면 답이 바뀜. 3곳(Akamai)은 네트워크를 바꾸면 바뀜.
  • DASH: 서버는 영상을 여러 비트레이트의 청크로 나눈다. 매니페스트가 URL을 나열한다. 클라이언트는 측정한 대역폭으로 청크마다 비트레이트를 고른다.

D6 왜 — 시험식 답

질문답
루트는 왜 주소를 주지 않는가?루트는 TLD 위임만 안다. 각 존의 데이터는 그 존의 소유자가 보관한다. 이렇게 부하와 관리를 나눈다.
DNS는 왜 UDP인가?짧은 질문 하나, 짧은 답 하나다. 핸드셰이크 비용이 없다. TCP는 큰 응답(TC=1)과 존 전송에 쓴다.
왜 캐시하는가?루트·TLD 질의를 없애고 지연을 줄인다. TTL은 답이 얼마나 오래되어도 되는지 제한한다.
리졸버마다 답이 왜 다른가?CDN은 클라이언트 IP가 아니라 리졸버 IP를 본다. 리졸버에 가까운 복제 서버를 고른다.

  • Stop-and-wait: 한 번에 패킷 하나만 보낸다. 쉽다. 느리다. RTT와 타임아웃마다 채널이 논다.

  • 중복 데이터: 다시 ACK한다(앞의 ACK가 손실되었을 수 있다). 다시 붙이지 않는다.
  • 중복 ACK: acked[seq]=True를 다시 해도 문제없다.
  • 실습 채널: 손실 10%, 중복 3%, 순서 뒤바뀜. 선택: SR, 윈도우 8, 타임아웃 40스텝.
  • 측정: 데이터 250패킷에 326번 전송 = 1.30배(손실 42, 중복 13).
  • "받은 대로 붙이는" 수신기는 손실에서 먼저 깨졌다(4번째 패킷). 중복은 9번째.

T2 타임아웃

공식은 A2를 본다. 재전송한 세그먼트로는 SampleRTT를 재지 않는다(Karn). 타임아웃이 나면 간격을 2배로 한다.

T3 세그먼트, 핸드셰이크, 종료

  • Seq = 데이터 첫 바이트의 번호. ACK = 다음에 받을 바이트 번호(누적).
  • SYN과 FIN은 각각 순서 번호 1개를 쓴다.
클라이언트                       서버
SYN      seq=x            →
         ←  SYN+ACK seq=y, ack=x+1
ACK      seq=x+1, ack=y+1 →     (데이터를 실어도 됨)
종료: FIN → ACK, FIN ← ACK; 클라이언트는 TIME_WAIT(2·MSL) 대기
  • ISN은 무작위이고 0이 아니다. 위조 세그먼트를 막는다. 같은 포트 쌍을 쓴 이전 연결의 옛 세그먼트가 섞이는 것을 막는다. 측정 ISN: 1111356914, 3798358670.
  • SYN 옵션: MSS(예: 1460), window scale(shift), SACK permitted, timestamps. MSS·WS는 SYN/SYN-ACK에만 온다.
  • 플래그: SYN, ACK, FIN, RST, PSH, URG (+ ECE, CWR).
  • 핸드셰이크 시간 ≈ 1 RTT다. 모든 연결에 더해진다.

T4 흐름 제어 vs 혼잡 제어

  • 흐름 제어는 수신기 버퍼를 보호한다: rwnd(헤더에 있음).
  • 혼잡 제어는 네트워크를 보호한다: cwnd(송신자만 앎, 헤더에 없음).
  • 측정: rwnd ≈ 4.6 MB(scale ×1024). 전송 중 최대 ≈ 193 KB. 그래서 제한 요인은 rwnd가 아니라 slow start 중인 cwnd였다. BDP ≈ 168 KB.

I · 5주차 · IP, CIDR, NAT, DHCP §4.3

I1 IP 헤더

  • IPv4: 옵션 없이 20 B. 필드: version, header length, TOS(DSCP/ECN), total length, ID, flags(DF, MF), fragment offset(8바이트 단위), TTL, protocol, header checksum, src, dst.
  • 라우터마다 TTL을 1 줄인다. 0이 되면 패킷을 버리고 ICMP 11을 보낸다.
  • IPv6: 40 B 고정. 128비트 주소. flow label, hop limit, next header. 헤더 체크섬 없음. 라우터는 단편화하지 않는다(출발지가 PMTU 탐색으로 한다). 터널링으로 IPv6를 IPv4에 싣는다.
  • 라우터: 입력 포트(조회) → 스위칭 패브릭(메모리, 버스, 크로스바) → 출력 큐. 입력 큐에서 HOL 블로킹. 스케줄링: FIFO, 우선순위, 라운드 로빈, WFQ.

I2 CIDR과 범위

  • a.b.c.d/p: 앞 p비트가 네트워크, 나머지가 호스트다.
  • 네트워크 주소: 호스트 비트 모두 0. 브로드캐스트: 호스트 비트 모두 1. 사용 가능 = 그 사이.
  • p가 0–32 밖이면 거부한다(R1). 호스트 비트가 켜져 있으면 거부한다: 163.152.6.5/24는 네트워크가 아니라 호스트다(R2).
  • /31(RFC 3021, 점대점): 두 주소 모두 호스트 → (net, net+1, None).
  • /32: 호스트 하나 → (addr, addr, None).

I3 가장 긴 접두사 일치 (LPM)

  • 접두사는 겹칠 수 있다. 라우터는 일치하는 것 중 가장 긴(가장 구체적인) 접두사를 고른다.
  • 0.0.0.0/0은 모두와 일치한다. 다른 일치가 있으면 진다.
  • 예: 10.20.30.70은 /0, /8, /16, /24, /26과 일치 → /26 lab-rack-2.
  • 같은 네트워크·같은 길이에 다음 홉이 다르면 모호하다. 내 add()는 ValueError를 낸다.

  • 게이트웨이는 반드시 내 서브넷 안에 있다. 호스트는 서브넷 밖으로 가는 프레임을 게이트웨이 MAC으로 보낸다.

R · 6주차 · 라우팅 §5.2–5.4, §5.6

R1 링크 상태 (Dijkstra)

  • 라우터마다 자기 링크 비용(LSA)을 플러딩한다. 모든 라우터가 같은 지도를 갖는다.
  • 각 라우터가 혼자 Dijkstra를 돌린다. 결과는 경로가 아니라 목적지마다 다음 홉 하나다.
  • 복잡도: 단순 구현 O(n²), 힙 사용 O((n+e) log n).
  • 다음 홉은 반드시 직접 이웃이다. 출발지 자신은 표에 없다.
  • 인접 관계를 경로로 쓰지 않는다: u–w 직접 = 5, u–x–y–w = 3 → w의 다음 홉은 x.
  • 내 동점 규칙: 첫 홉 이름이 가장 작은 쪽. 실제 OSPF: 같은 비용의 다음 홉을 모두 설치(ECMP)하고 흐름마다 해시로 나눈다.
  • 비용 = 트래픽 부하이면 경로가 진동할 수 있다.
교과서 그래프 (§5.2.1)vwxyz
u에서 비용23124
u의 다음 홉vxxxx
u–x 끊긴 뒤vv (동점 5)vvv

링크: u-v2 u-w5 u-x1 v-w3 v-x2 w-x3 w-y1 w-z5 x-y1 y-z2

Dijkstra 손 계산: 표의 행 = 단계. N' = 확정된 노드 집합. 단계마다 D(·)가 가장 작은 노드를 N'에 넣는다. D(v) = min(D(v), D(w) + c(w,v))로 갱신한다. p(v) = 직전 노드를 적는다.

R2 거리 벡터 (Bellman-Ford)

D_x(y) = min (이웃 v에 대해) { c(x,v) + D_v(y) }
  • 노드는 자기 벡터를 이웃에게만 보낸다. 비동기, 반복, 분산.
  • 좋은 소식은 빨리 퍼진다. 나쁜 소식은 느리게 퍼진다: 무한 카운트.
  • Poisoned reverse: z가 y를 거쳐 x로 가면, z는 y에게 "Dz(x) = ∞"라고 알린다. 노드 3개 이상의 루프는 막지 못한다.
  • LS vs DV: LS는 O(nE) 메시지, 전체 지도를 알고 각자 계산한다(견고). DV는 이웃에게만 보내고 수렴이 느리며 오류가 퍼진다.

R3 OSPF

  • AS 내부 링크 상태 프로토콜. IP 위에서 바로 동작한다(프로토콜 89).
  • Hello로 이웃을 찾는다(10초). Dead 간격(40초) 동안 hello가 없으면 이웃 down.
  • LSA를 영역 전체에 플러딩한다. 라우터마다 SPF를 계산한다. 인증을 지원한다.
  • 계층: 영역(area). Area 0 = 백본. 영역 경계 라우터가 요약한다.
  • 관리자가 링크 비용을 정한다. ECMP를 허용한다.

R4 BGP (AS 간)

  • AS 사이는 eBGP, AS 안은 iBGP. TCP 179를 쓴다. 경로 벡터 방식.
  • 경로 = 접두사 + 속성. AS-PATH(루프 감지), NEXT-HOP.
  • 선택 순서: local preference(정책) → 가장 짧은 AS-PATH → 가장 가까운 NEXT-HOP(hot potato) → 기타.
  • 정책: AS는 고객이 아닌 쪽의 통과 트래픽을 실어 주지 않는다.
  • AS 내부는 성능을 중시한다. AS 간은 정책을 중시한다. 계층 구조로 규모를 감당한다.
  • SDN: 중앙 컨트롤러가 흐름 표(일치 + 동작, OpenFlow)를 계산한다.

R5 ICMP와 traceroute

  • traceroute는 TTL = 1, 2, 3 …인 탐침을 보낸다. TTL이 0이 된 라우터가 ICMP 11(TTL 초과)을 보낸다.
  • 목적지 호스트는 ICMP 3/3 포트 도달 불가(UDP)나 echo reply를 보낸다. 그러면 traceroute가 멈춘다.
  • * * * 이유 1: 라우터가 전달은 하지만 ICMP를 보내지 않는다. 뒤 홉은 다시 답한다.
  • * * * 이유 2: 목적지 근처 방화벽이 탐침을 버린다. 뒤 홉도 답하지 않는다.
  • 한 홉에서 +100 ms 정도 뛰면 해저 케이블이다. 측정: hop 7→8에서 +114 ms(MIT 경로).
  • 애니캐스트 1.1.1.1: 13홉, 12 ms → 복제 서버가 국내(ICN)에 있다.

  • 사건 사이에 dist(출발지부터 비용)를 보관한다. 표 = dist와 그래프의 함수다.

E · 7주차 · 이더넷, ARP, 스위치 §6.3–6.4

E1 MAC과 프레임

  • MAC = 48비트. 계층이 없다(flat). NIC에 정해져 있다. 브로드캐스트 = ff:ff:ff:ff:ff:ff.
  • IP = 어디에 있는가(계층형, 네트워크마다 바뀜). MAC = 누구인가(고정, 같은 링크 안에서만 씀).
| Preamble 8 | 목적지 MAC 6 | 출발지 MAC 6 | Type 2 | Data 46–1500 | CRC 4 |
  • 이더넷은 비연결형이고 비신뢰적이다. CRC가 틀린 프레임은 수신기가 버린다. ACK가 없다.
  • 이더넷에는 TTL이 없다. 루프가 있으면 프레임이 끝없이 돈다 → STP를 쓴다.

E2 ARP (같은 서브넷에서 IP → MAC)

요청 (request)응답 (reply)
목적지 MACff:ff:ff:ff:ff:ff (브로드캐스트)요청자 MAC (유니캐스트)
받는 쪽서브넷의 모든 호스트요청자 하나
내용"172.16.19.1 누구? …에게 알려 줘""172.16.19.1은 …에 있다"
  • 요청에 요청자 MAC이 들어 있다. 그래서 응답은 브로드캐스트할 필요가 없다.
  • ARP 표 = 소프트 상태. 항목마다 만료 시간이 있다. 트래픽이 필요할 때 다시 생긴다.
  • 목적지가 서브넷 밖이면 호스트는 서버가 아니라 게이트웨이를 ARP로 찾는다. 프레임 목적지 MAC = 게이트웨이, IP 목적지 = 서버.
  • 그래서 먼 웹 서버는 ARP 표에 절대 없다. 표는 작게 유지된다.
  • 측정: 비운 뒤 처음 돌아온 항목 = 게이트웨이 172.16.19.1(이전 2개, 이후 1개).
  • 규모: 브로드캐스트 부하 ∝ 호스트 수. 호스트당 분당 1요청이면 /24 → 호스트마다 분당 254개, /16 → 초당 약 1,000개.
  • 다른 서브넷으로 보내기: IP는 A→B 그대로. 프레임 1: 출발지 MAC A, 목적지 MAC 라우터. 라우터가 프레임 2를 만든다: 출발지 MAC 라우터 출력 포트, 목적지 MAC B.

E4 링크 계층 기타

  • 패리티: 1비트로 홀수 개 오류를 감지한다. 2차원 패리티는 1비트 오류를 고친다.
  • 인터넷 체크섬: 16비트 1의 보수 합.
  • CRC: 생성자 G(r+1비트)를 고른다. D·2r XOR R을 보낸다. R = (D·2r / G)의 나머지(mod 2). r+1비트 미만의 연속 오류를 감지한다.
  • 다중 접속: 채널 분할(TDMA, FDMA), 랜덤(ALOHA, CSMA/CD), 차례(폴링, 토큰).
  • Slotted ALOHA 최대 효율 1/e ≈ 0.37. Pure ALOHA 1/(2e) ≈ 0.18.
  • CSMA/CD 백오프: m번째 충돌 뒤 K를 {0,…,2min(m,10)−1}에서 고른다. K·512비트 시간 기다린다.
  • VLAN 802.1Q: 4바이트 태그, 12비트 VLAN ID. 트렁크 포트는 여러 VLAN을 싣는다.
  • STP: 스위치들이 신장 트리를 만들고 루프가 되는 포트를 막는다.

E3 학습 스위치 (Task 1)

  1. 학습: 출발지 MAC → 들어온 포트, 현재 시각.
  2. 들어온 포트로는 절대 내보내지 않는다.
  3. 목적지가 브로드캐스트 → 나머지 모든 포트.
  4. 아는 목적지 → 그 포트 하나(그 포트가 들어온 포트면 아무 데도 안 보냄, 필터링).
  5. 모르는 목적지 → 나머지 모든 포트(플러딩).
  • 장비가 옮기면 (포트, 마지막 관측 시각)을 덮어쓴다 → 바로 새 포트를 믿는다(R3).
  • 에이징: 300초보다 오래된 항목을 지운다(R4). 같은 시각 정보를 반대로 읽는 것이다.
  • 브로드캐스트 주소는 출발지로 학습하지 않는다.
  • 왜 들어온 포트로 내보내지 않는가? 그 너머의 목적지는 이미 프레임을 받았다. 그 너머 스위치는 출발지를 틀린 포트로 배운다. 두 스위치가 모르는 프레임을 서로 되돌리면 끝없이 돈다(TTL 없음).
  • 왜 스위치는 플러딩하고 라우터는 버리는가? MAC은 계층이 없다. "모른다" = "아직 못 배웠다"다. 플러딩해도 LAN 안에서 끝난다. 라우터 표는 라우팅 프로토콜이 채운다. 경로 없음 = 도달 불가다. 인터넷 전체로 플러딩할 수도 없다.
  • 시간 기반 에이징의 비용: 받기만 하는 장비는 잊힌다 → 그 장비로 가는 프레임이 플러딩된다. 조용히 옮긴 장비 → 만료 전까지 옛 포트로 가서 사라진다. 더 직접적인 방법: 포트 down 시 그 포트 항목 삭제, STP 토폴로지 변경 알림.
  • 스위치 vs 라우터: 스위치 = 2계층, 설정 없이 동작, 필터링, 트리 토폴로지 필요. 라우터 = 3계층, 설정 필요, 어떤 토폴로지도 가능, 브로드캐스트를 격리.

E5 꽉 찬 표 (Task 3)

  • 포트 48, 장비 400, 용량 64. 트래픽이 치우쳐 있다(소수 장비가 대부분을 보냄).
  • baseline: 가장 먼저 들어온 항목을 내보낸다(FIFO). 들어온 시각은 앞으로 필요할지와 상관없다.
  • 내 방식: MAC마다 출발지·유니캐스트 목적지 등장 횟수를 count-min sketch(4×256)로 센다. 추정치가 가장 작은 항목을 내보낸다. 20,000번마다 모든 카운터를 반으로 줄인다.
  • 학습 거절: 새 출발지는 횟수가 내보낼 항목보다 클 때만 들어온다. 거절 3,599번.
  • 결과: 낭비 전달 323,380 → 159,712(−51%). LRU만 쓰면 −32%. 누락 0.
  • sketch를 쓰는 이유: 메모리가 고정된다. MAC마다 카운터를 두면 가짜 MAC마다 커진다.
  • MAC flooding 공격: 가짜 출발지 MAC을 계속 바꿔 프레임을 보낸다. 진짜 항목이 표에서 밀려난다. 진짜 호스트로 가는 프레임이 공격자 포트로도 플러딩된다 → 공격자가 엿본다. 대책: 포트 보안(포트당 MAC 수 제한).

def to_int(a):
    p = a.split(".")
    if len(p) != 4: raise ValueError(a)
    v = 0
    for x in p:
        if not x.isdigit() or int(x) > 255: raise ValueError(a)
        v = (v << 8) | int(x)
    return v

def to_str(v):
    return ".".join(str((v >> s) & 0xFF) for s in (24, 16, 8, 0))

def mask(p):
    return (0xFFFFFFFF << (32 - p)) & 0xFFFFFFFF

C6 parse_cidr, network_range, LPM 표

def parse_cidr(c):
    addr, pl = c.split("/")
    p = int(pl)
    if not 0 <= p <= 32: raise ValueError("prefix")      # R1
    net = to_int(addr)
    if net & ~mask(p) & 0xFFFFFFFF: raise ValueError("host bits")  # R2
    return net, p

def network_range(c):
    net, p = parse_cidr(c)
    last = net | (~mask(p) & 0xFFFFFFFF)
    if p == 32: return to_str(net), to_str(net), None
    if p == 31: return to_str(net), to_str(last), None
    return to_str(net+1), to_str(last-1), to_str(last)

class ForwardingTable:
    def __init__(self): self.by_len = {}       # p -> {net: hop}
    def add(self, c, hop):
        net, p = parse_cidr(c)
        b = self.by_len.setdefault(p, {})
        if net in b and b[net] != hop: raise ValueError("모호함")
        b[net] = hop
    def lookup(self, a):
        x = to_int(a)
        for p in sorted(self.by_len, reverse=True):   # 긴 길이부터
            h = self.by_len[p].get(x & mask(p))
            if h is not None: return h               # 첫 일치에서 멈춤
        return None

class Trie:                         # 작업량 <= 32단계
    def __init__(self): self.root = [None, None, None]  # [0-자식, 1-자식, hop]
    def add(self, net, p, hop):
        n = self.root
        for i in range(p):
            b = (net >> (31 - i)) & 1
            if n[b] is None: n[b] = [None, None, None]
            n = n[b]
        n[2] = hop
    def lookup(self, a):
        n, best = self.root, self.root[2]
        for i in range(32):
            n = n[(a >> (31 - i)) & 1]
            if n is None: break
            if n[2] is not None: best = n[2]   # 지금까지 가장 긴 일치 기억
        return best

def walk(name):
    servers = ROOTS
    for _ in range(MAX_DEPTH):                 # R6 깊이 제한
        reply = first_reply(servers, name)     # R4: 응답 없으면 다음 서버
        ans = reply.answer
        if name의 A 레코드가 ans에 있음: return ("A", ip)
        if ans에 CNAME 있음: return ("CNAME", target)   # R5: 루트부터 다시
        ns = reply.authority의 NS 이름들
        glue = [reply.additional에서 ns의 A]
        servers = glue if glue else [resolve(ns[0])]  # R3: glue 없음 = 새 탐색
    raise RuntimeError("depth")

def resolve(name):
    for _ in range(MAX_CNAME):
        kind, v = walk(name)
        if kind == "A": return v
        name = v
    raise RuntimeError("CNAME loop")

class YourControl:
    def __init__(self):
        self.window = 1.0; self.slow_start = True; self.quiet = 0

        if self.quiet > 0: self.quiet -= 1

C8 Dijkstra + 첫 홉 (6주차 T1)

import heapq
def dijkstra(g, s):
    dist = {s: 0}; pq = [(0, s)]; done = set()
    while pq:
        c, n = heapq.heappop(pq)
        if n in done: continue
        done.add(n)
        for v, w in g[n].items():
            if v not in done and c + w < dist.get(v, float("inf")):
                dist[v] = c + w; heapq.heappush(pq, (c + w, v))
    del dist[s]; return dist                  # 도달 불가 노드는 없음

def forwarding_table(g, s):
    best = {s: (0, "")}; pq = [(0, "", s)]; done = set(); t = {}
    while pq:
        c, hop, n = heapq.heappop(pq)
        if n in done: continue
        done.add(n)
        if n != s: t[n] = hop
        for v, w in g[n].items():
            if v in done: continue
            cand = (c + w, v if n == s else hop)   # 첫 홉을 물려받음
            if cand < best.get(v, (float("inf"), "")):  # 동점: 작은 홉 이름
                best[v] = cand; heapq.heappush(pq, (cand[0], cand[1], v))
    return t

def link_down(g, a, b):
    g = {n: dict(e) for n, e in g.items()}   # 복사, 원본 변경 금지
    g[a].pop(b, None); g[b].pop(a, None); return g
