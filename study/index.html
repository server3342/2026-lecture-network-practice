0.2계층 모델: 세 주를 묶는 그림

인터넷은 일을 계층(layer)으로 나눕니다. 각 계층은 바로 아래 계층의 서비스를 사용합니다. 3·4·5주차는 위에서부터 한 계층씩 내려갑니다.

0.3주차별 페이지

3주차 · DNS와 CDN

계층 구조, 재귀/반복 질의, 레코드, 위임과 glue, CNAME, 캐시와 TTL, CDN 유도

실습: 반복 리졸버 · 유도 측정 · TTL 캐시

4주차 · TCP

포트, UDP, 신뢰적 전송, 선택적 반복, 핸드셰이크, 흐름 제어, 혼잡 제어, QUIC

실습: 신뢰적 전송 · 링크 측정 · 혼잡 제어

5주차 · IP와 NAT

라우터 내부, IPv4 주소, 서브넷과 CIDR, 최장 프리픽스 일치, DHCP, NAT, IPv6

실습: 서브넷과 LPM · 내 주소와 DHCP · 빠른 LPM

0.4세 주를 하나로 연결하기

4주차 Task 2에서 curl https://speed.cloudflare.com/...을 실행했습니다. 그때 다음 순서로 일이 일어납니다. 색은 주차를 뜻합니다.

3주차 DNS 4주차 TCP 5주차 IP·NAT
  1. DHCP. Wi-Fi에 들어올 때 노트북은 주소 172.16.25.130/24, 게이트웨이 172.16.25.1, DNS 서버 주소를 받았습니다.
  2. DNS. curl이 로컬 DNS 서버에 이름을 재귀 질의합니다. 캐시에 없으면 로컬 DNS 서버가 루트 → .com → 권한 서버로 반복 질의합니다. → curl의 time_namelookup
  3. 포워딩 결정. 목적지가 자기 서브넷 밖입니다. 노트북은 패킷을 기본 게이트웨이로 보냅니다.
  4. TCP 핸드셰이크. SYN → SYN-ACK → ACK. ISN을 정하고 MSS와 윈도우 스케일을 교환합니다. → curl의 connect_s
  5. NAT. 캠퍼스 경계 라우터가 출발지 172.16.25.130:포트를 163.152.233.xxx:새 포트로 바꾸고 변환 표에 기록합니다.
  6. 라우터마다 포워딩. 각 라우터는 목적지 주소에 최장 프리픽스 일치를 적용합니다. IP 헤더의 TTL을 1 줄입니다.
  7. 데이터 전송. 슬로 스타트로 cwnd가 RTT마다 두 배가 됩니다. 수신 윈도우는 4.6 MB였지만 실제로 보낸 양은 약 193 KB였습니다.
  8. 응답의 귀환. 응답은 NAT 변환 표를 거쳐 다시 172.16.25.130으로 갑니다.
